I haven’t seen your translation scripts yet, so I can’t give you the exact command. Here’s how to find it, step by step. If anything looks unclear, paste the output here and I’ll tell you exactly what to run.

Step 1: Find the translation commands

From D:\tdgmain in Git Bash:

bash
grep -n "i18n\|translat" package.json

This lists the scripts in package.json that deal with translation. You’re looking for one that runs i18n-auto.mjs without --status-only. It’s often called i18n, i18n:auto or translate.

Step 2: Check what’s missing

This is the same check your build runs, on its own:

bash
node scripts/i18n-prepare.mjs && node scripts/i18n-auto.mjs --status-only

It should report that new English sentences (from the mute page and the feature list) have no translations yet in your languages (ar, bn, de, fr and so on).

Step 3: See how the script wants to be run
bash
head -40 scripts/i18n-auto.mjs
grep -n "process.env\|--" scripts/i18n-auto.mjs | head -30

The first command shows the comment at the top of the script, which usually explains its options. The second shows which options it accepts and whether it needs an API key (a line like process.env.SOMETHING_API_KEY). If it does, the key is normally kept in a .env.local file in your project folder.

Step 4: Run the translation

Use the script name you found in step 1, for example:

bash
npm run i18n:auto

If there’s no such script, run the file directly without the status flag:

bash
node scripts/i18n-auto.mjs
Step 5: Check the result
bash
node scripts/i18n-auto.mjs --status-only

It should now report nothing missing. Then start the site and look at a couple of languages:

bash
npm run dev
http://localhost:3000/en/resources/mute-zoom-meeting-hotkey
http://localhost:3000/ar/resources/mute-zoom-meeting-hotkey (check right-to-left looks right)
http://localhost:3000/de/resources/mute-zoom-meeting-hotkey

On each page, the hotkeys in the tables should still read CTRL+ALT+K and so on. In the normal sentences, check that the translation didn’t damage them, for example by turning “Ctrl+Alt+K” into something unreadable.

Step 6: Build
bash
npm run build

If npm run build succeeds, the site is ready to publish. Remember the testing checklist from before: publish only after the new Magic Toolbar version is released.
